=== SWAGGER: КРОКИ ТА ДАНІ ДЛЯ ВСТАВКИ ===

1. Авторизація (Лаба 10 - JWT)
- Ендпоінт: POST /api/v1/auth/login
- Request Body:
{"username":"admin_oleg","password":"admin123"}
- Дія: Скопіювати значення "token" з відповіді -> кнопка Authorize вгорі -> вставити токен.
- Коментар: Генерація JWT токена без збереження стану на сервері (Stateless).

2. Отримання замовлень (Лаба 8 - REST API & DTO)
- Ендпоінт: GET /api/v1/orders
- Параметри: search (пустий), status (--)
- Дія: Натиснути Execute.
- Коментар: Повертає список замовлень через типізований OrderResponse DTO.

3. Фільтрація (Лаба 9 - Spring Data JPA)
- Ендпоінт: GET /api/v1/orders
- Параметр: search = Apple
- Дія: Натиснути Execute.
- Коментар: Пошук по сутностях через ILIKE запит у репозиторії.

4. Публічний доступ (Лаба 10 - Security Rules)
- Ендпоінт: GET /api/v1/tracking/{trackingCode}
- Параметр: trackingCode = TRK-B2C44E
- Дія: Натиснути Execute без авторизації.
- Коментар: Доступний для анонімних клієнтів без передачі Bearer токена.

5. Зміна статусу (Лаба 8 - Життєвий цикл)
- Ендпоінт: PATCH /api/v1/orders/{id}/status
- Параметр: id = 3
- Request Body:
{"status":"IN_PROGRESS"}
- Коментар: Оновлення стану замовлення через Enum OrderStatus.

6. Списання зі складу (Лаба 9 - Транзакції @Transactional)
- Ендпоінт: POST /api/v1/orders/{id}/parts
- Параметр: id = 3
- Request Body:
{"sparePartId":1,"quantity":1}
- Коментар: Транзакційне списання залишку та перерахунок загальної вартості замовлення.

7. Перевірка валідації помилок (Лаба 9 - Validation)
- Ендпоінт: POST /api/v1/orders
- Request Body:
{"clientName":""}
- Коментар: Повертає 400 Bad Request від GlobalExceptionHandler при спрацюванні @Valid.

8. Перевірка RBAC захисту (Лаба 10 - Ролі)
- Ендпоінт: DELETE /api/v1/orders/{id}
- Параметр: id = 5
- Коментар: Захищений метод з @PreAuthorize("hasRole('ADMIN')").
